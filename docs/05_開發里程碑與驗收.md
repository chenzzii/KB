# 開發優先順序與驗收標準

## P0：研究資料固定及專案啟動

- [ ] npm 工程可在 Windows Chrome 啟動。
- [ ] 25 兵種映射保留全數值；14 法術、8 神器、4 職業、17 敵將一對一對照可讀。
- [ ] 4 項參數異常顯示成明確 warning，未偽造或靜默自動修復。
- [ ] 單機本地運作，不需要登入、網路 API 或後端。

驗收：`python scripts/validate_pack.py` 與 `npm run validate:data` 通過；基本兵表可切換來源名/新名。

## P1：第一個真正可玩的「戰鬥切片」（第一輪 Codex 任務）

- [ ] 6×5 戰鬥棋盤，雙方最多 5 隊，至少可以選 8 種不同特性的中國兵種（資料完整保留 25 種）。
- [ ] 行走、阻擋、近戰、遠射、回合、反擊、受傷及陣亡、輸贏與重開。
- [ ] 可交換五個隊位；能合併及拆分滿血部隊；統率力即時計算。
- [ ] 進攻與反擊都輸出事件日誌、可讀 seed、規則版本。
- [ ] 玩家可在「中國版名稱」與「來源名稱」切換，同一場戰鬥其數值不變。
- [ ] 固定 seed 重播完全一致，能匯出／匯入 replay JSON。
- [ ] 繁中 UI、基本鍵盤與滑鼠操作，不依賴美術生成。

驗收：`npm test`、`npm run build` 成功；開啟 `npm run dev` 可以玩完一場戰鬥，重播結果一致。**若 special ability 未完成必須顯式標成尚未實作，不能悄悄不生效**。

## P2：完整戰鬥與規則驗證

- [ ] 全 25 兵種上場，所有技能 `fly/undead/absorb/regen/magic/leech/scythe/immune` 有程式及測試。
- [ ] 14 個法術全部有已實作／尚待核對標籤；不確定效果禁止冒充原作。
- [ ] 士氣矩陣、神器、AI 的行為皆有證據記錄。
- [ ] 加入傷害批次模擬（同 seed 可重播 10,000 場測試）。

## P3：小型大地圖冒險

- [ ] **原創** 32×32 地圖；至少 2 城、3 招募點、1 首領、1 懸賞，均與原版地圖不同。
- [ ] 每日步數、每週經濟／軍餉／兵源補充、賞金與招募 UI。
- [ ] 1 條有至少兩個解法的任務，1 件原創神器，存檔與讀檔。
- [ ] 起碼能有「招募→探索→戰鬥→領賞→續行」完整迴圈。

## P4：特色強化與內容擴充

- [ ] 派系關係、城池占領、天候地形、外交／招安／討伐三條互斥事件分支。
- [ ] 兵種平衡調整檔，讓新作能在保留原數值研究基準下發展自己的策略特色。
- [ ] 原創音效、美術與故事；提供版本與授權聲明，適用網頁公開展示。

## 測試重點（Vitest）

1. source IDs 必須恰好 0–24，無重複／無漏兵種；原始數值未改變。
2. 兵團交換兩次回到同樣序列；合併與拆分前後各單位總數不變。
3. 遠射 0 彈藥不得繼續射擊；飛行與不可穿透等行為待來源驗證。
4. 兵數 0、負數、無限大、NaN、過大整數都不接受。
5. HP 殘餘、受傷、死亡數不能無限或負數；反擊至多遵守指定限制。
6. 同 seed+初始狀態+命令列表相同，事件與最終狀態 hash 完全一致。
7. 100 統率 + 10 個 HP10 弓手視為邊界例；11 個視為超額例，待對照引擎確定失控處置。
8. 士氣矩陣尚未確認時，UI 顯示『未經驗證』並避免導入自說自話的負面效果。
9. `troop14.spoils_raw` 和法術 6 重複價錢須保留且有診斷。
10. 新作與原版模式切換時數值漂移差異明列，禁止破壞基準參數。
