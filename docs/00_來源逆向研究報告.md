# 《御封戰將》Windows 繁中整合包：第一輪靜態逆向研究報告

**來源**：使用者提供 `KingsBounty-CHT-full-windows-x64.zip`；僅靜態讀取 ZIP 內容，不執行其中的 EXE 或 DLL。
**研究目標**：取得可重製遊戲運作的數值及資料模型，並區分「繁中 openKB 的 free 模組」和「1990 DOS 原版真正程式行為」。

## 1. 專案結論

- `openkb.exe` 為 Windows x86-64 PE 執行檔，`play.bat` 會透過 `openkb.ini` 指定 `data/free/` 模組。
- `data/KB.EXE` 為 MS-DOS MZ 執行檔；含 `Version 1.00`、`Copyright (C) 1990 New World Computing, Inc.`、英文兵種及 UI 字串。它的 107,533-byte 大小與目前可核對之 1990 壓縮版及 1995 版都不同，因此僅可判定它是 1990 系 DOS 程式的候選版本，尚未驗證完全一致。
- `data/256.CC`、`data/416.CC` MD5 與 openKB 歷史資料中 1990 DOS 原版一致；`data/kb.bin` 與其中列出的 1991 Mega Drive ROM 一致。
- `data/free/*.ini` 是正在啟用之 free 模組的中文參數資料；這些是重製引擎參數，**不得直接當成原版 DOS 執行檔的運算證據**。
- `data/free/land.tmx` 有 4 層 64×64 地圖；另有 26 城堡、26 城鎮、17 通緝犯。

## 3. 已發現的 4 處資料異常

1. **`data/free/troops.ini` / `[troop7]` / `file`**：sprite filename not specified; perhaps fallback exists。處置：inspect loader fallback。
2. **`data/free/troops.ini` / `[troop14]` / `spoils`**：non-integer value '10s0'。處置：check original value; do not auto-correct。
3. **`data/free/troops.ini` / `[troop17]` / `file`**：named sprite 'troll.png' is absent from data/free。處置：check module fallback or spelling。
4. **`data/free/spells.ini` / `[spell6]` / `gold`**：duplicate assignment on line 42: '250' then '2000'。處置：check parser precedence and intended value。

尤其 `troop14` 的 `spoils = 10s0` 是不能轉成整數的字串；目前轉換器把數值寫成 `null`，並另外保存 `spoils_raw`，**沒有擅自猜為 100**。
`spell6` 的 `gold=250` 和 `gold=2000` 兩筆都保留於 `all_gold_assignments`；因 INI 解析器對重複鍵的行為不確定，需檢查 `openkb` 讀值邏輯才可判定實際費用。

## 4. 二進位檔鑑定

| 文件 | 大小 (B) | MD5 | 目前意義 |
|---|---:|---|---|
| `data/KB.EXE` | 107,533 | `714cd13665f8d042dfe1a26b9a50f33c` | DOS 原版候選；與歷史列出的兩個常見版本雜湊不符 |
| `data/256.CC` | 281,551 | `36a360da4d53325b89ae7b30656e7a78` | 與 openKB 1990 DOS VGA 檔 MD5 相符 |
| `data/416.CC` | 340,983 | `def1c7f5b1c6ed719a24b4a6371bb451` | 與 openKB 1990 DOS CGA/EGA 檔 MD5 相符 |
| `data/kb.bin` | 524,288 | `1bb8e1e5d41bbeff2e452935bddd9883` | 與 openKB Genesis ROM MD5 相符 |
| `openkb.exe` | 1,499,152 | `3eb1ed8c533511ca50abb7f7ab66911a` | Windows 64-bit 重新實作引擎 |

openKB 歷史記錄：1990 DOS `KB.EXE` 常見壓縮檔為 79,839 bytes（MD5 `b415c8e920bfce24affdd281bf55a78`）；1995 發行版為 113,718 bytes（MD5 `691a88edbf0a2a1244dd1239ed4421f0`）。**不一致不表示惡意，也不代表一定被修改；可能是不同封裝或解壓版本**，目前尚無證據能確認其精確來源。

DOS 執行檔中可直接定位的字串偏移（十六進位，0-based file offsets）：`Version 1.00` 0x13A73、`Peasants` 0x13BD7、`Dragons` 0x13C91、`Leadership` 0x1873D。可當成 Ghidra/IDA 靜態分析的字串定位錨點。

## 5. 遊戲引擎與原版的分層驗證策略

1. **設定資料層**：直接使用本包 `game_parameters.json` 作為可重製基準；檢查 4 處異常與素材 fallback。
2. **運作規則層**：讀公開 `open-king-bounty-cht` / `openKB` 的 C 源碼，確認實際讀取、薪資、統率力、回合、士氣、傷害、AI、地圖生成與亂數公式。
3. **DOS 原版驗證**：研究 `KB.EXE` 的 x86 16-bit 程式，透過靜態分析 + DOSBox 偵錯器動態實驗，針對輸入/輸出建立 test vectors；不要在主要工作電腦直接執行來源不明的程式。
4. **跨版本測試**：相同兵種與戰局在 DOS、openKB、OpenBounty 逐項對照。不要把 Genesis、Amiga 與 DOS 的系統差異混在同一套規則。
5. **原創新作**：遊戲規則與美術/UI/故事分離，先實作純 TypeScript 或 Go 規則引擎；再建中國奇幻內容的獨立資料包。

### 第一批最值得驗證的運作問題

- 統率力使用 `每隊兵數×HP` 控制，邊界相等時是允許或超額？失控部隊行為及其撤離時機。
- 每週軍餉是否由單價取整計算？扣錢前後順序、欠餉後的部隊行為。
- 技能等級如何參與近戰/遠程傷害、骰值、護盾與士氣倍率的計算，以及整數捨入順序。
- 兵種組別 A~E 的混編士氣判斷及修正次序。
- 費用、地圖移動、週次、怪物增長、寶箱、佔城、升階和追捕目標生成的亂數呼叫順序。
- 神器效果：`Book of Necros` / `Ring of Heroism` 在不同來源有不同說法，應把 DOS 原版執行結果作為最終標準，避免採用其他移植版的錯誤。

## 6. 建議的第一個可玩原型

**第 1 版先做「單張戰場 + 25 種兵種資料 + 可回放戰鬥日誌」**，不要從世界劇情開始。

- 以 `game_parameters.json` 建立查詢及驗證器，阻擋非法數值。
- 用固定亂數種子建立戰鬥測試，每次記錄傷害、死亡、反擊、士氣、技能與狀態效果。
- 規則以測試案例驗證，而不是先鎖死「應該是什麼」；所有未驗證規則標記 `hypothesis`。
- 之後改成原創中國風角色（武將／遊俠／方士／豪俠）與兵種，但最初先保留戰鬥設計參數作為比較基線。
