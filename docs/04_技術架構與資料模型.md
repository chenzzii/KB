# 技術架構與資料合約

## 建議

- 網頁優先：TypeScript + Vite + React（選單、兵表、事件）、PixiJS（2D 戰場與地圖）、Vitest（規則測試）。無後端單機運作，可離線擴充 PWA。
- **只把上面當實作建議**。如 Codex 需替換 React 或 PixiJS，必須確保核心規則完全不依賴 UI，且仍可在 Windows Chrome 執行。
- 內容全部放 JSON，以 schema + validator 防止 AI 修改時誤改 ID 或負數。

## 建議檔案結構（Codex 應建立）

```
src/
  core/engine.ts       # applyCommand(state, command) => {state, events}
  core/rng.ts          # seeded PRNG，禁止 Math.random 在計算中出現
  core/combat.ts      # move / attack / retaliate / death / turn
  core/armies.ts      # swap, merge, split, control, recruit
  core/economy.ts     # weekly settlement
  core/morale.ts      # versioned morale rules
  core/abilities.ts   # named, separately testable effects
  core/types.ts       # game data contracts
  core/rulesets.ts    # study vs chinese-enhanced
  content/load.ts     # read reference + mapping + overrides
  ui/*                # React components
  view/*              # Pixi stage renderer
  tests/*             # pure deterministic tests
public/assets/original/*   # 只允許自行創作內容；不得放舊遊戲素材
```

## 核心資料結構

```ts
type Evidence = 'source-extracted'|'manual-documented'|'open-source-implementation'|'dos-experiment-verified'|'unverified'|'proposed-new-game';
type UnitId = string;
type TroopDefinition = { id: UnitId; sourceTroopId: number; name: string; hp: number; attack: {min:number; max:number}; ranged?: {min:number;max:number;ammo:number}; moves:number; skill:number; gold:number; abilities:string[]; group:'A'|'B'|'C'|'D'|'E'; provenance:Evidence };
type ArmyStack = { instanceId:string; unitId:UnitId; count:number; damagedHp:number; statusEffects:Record<string,unknown>; position?:{x:number;y:number} };
type GameCommand = { type:'move'|'attack'|'ranged-attack'|'end-turn'|'swap-slots'|'merge'|'split'|'recruit'; actorId?:string; payload:unknown };
type Replay = { schemaVersion:string; rulesetVersion:string; dataHash:string; seed:string; initialState:unknown; commands:GameCommand[]; finalStateHash:string; events:unknown[] };
```

**資料導入策略**：`reference` 保持 frozen；解析 `content/troop_mapping.json` 的 sourceId，合併到 `TroopDefinition`；`data/generated/chinese_roster_reference_stats.json` 是為方便 Codex 起步已產生的完整格式，但日後應由 build script 產生，避免雙重真相。

## 命令與確定性

- `applyCommand` 必須純函式，輸入 state、command、rngState，回傳新 state、events 與新 rngState；不應依賴系統時間、UI 事件順序或浮點非決定行為。
- seed 可以用字串，但需明確定義 hash-to-uint32 + PRNG（如 xorshift32），還要處理 zero seed。關鍵取整順序須固定。
- 戰鬥回放必須記錄 sourceId、數值資料 hash、rulesetVersion 和每步結果。
- 存檔要有 schemaVersion，升版時提供 migration，避免更新後舊檔不可開。

## 遊戲流程模組

- World：32×32 tile 地圖、英雄所在位置、step/day/week、城池與招募點、隨機事件。
- Army：五隊、兵數、受傷、統率、資金、補員與週薪。
- Combat：6×5 格回合制、隊伍輪序、攻擊/遠射/反擊、死亡與擊敗、敵 AI。
- Narrative：任務旗標、敵人關係、派系狀態，與規則本體分離，未來支援不同結局。

## 模組界面必須分離

- 原版規則：戰鬥公式、士氣群組、統率、週薪、戰場格數。
- 新作內容：中國兵名、兵團視覺、世界觀、人物文本、場景與音樂。
- 新作平衡：特殊環境、派系外交、額外能力與改動註記。

## 測試／部署

- `npm run validate:data`、`npm run test`、`npm run build` 都必須在 CI 走。
- Windows 11 + Chrome 桌面首先支援；觸控與手機第二階段。
- GitHub Pages：使用 Vite `base` 或相對路徑，避免 SPA 深層路由 404；靜態存檔本機導出／匯入即可，初期不做伺服器與帳號系統。
